# D2E Cloud Functions / Backend Services

> Distilled from d2e-docs part 2 (cloud functions), 2026-06-14. See `00-overview` for context.

Each service is a Deno worker isolate in Trex with its own env/memory/CPU budget, wired via plugin manifest. Inter-service calls use HTTP (looping through Trex) or in-process Tokio IPC when co-located. Every request carries a correlation ID (UUID v4) and the original user token. Four families: Query Engine, Data Management, OHDSI Integration, Infrastructure.

## Query Engine
- **Analytics Service** (`/analytics-svc`) — platform front door + orchestrator. Resolves per-study DB creds, owns the connection for the request, turns SQL rows into chart JSON. Operations: aggregation, patient counting (multi-study parallel), patient lists, Kaplan-Meier (async, polls 10s/20min), box plots, data characterization, cohort create/list/compare/delete. CSV (injection-safe), Parquet, and ChaCha20-Poly1305 encrypted recontact exports. Calls Query Gen (IPC), Portal (every request), Bookmark (cascade on cohort delete), Job Plugins (KM). Leaf in the call graph.
- **Query Generation Service** — the SQL compiler; never touches the DB. **IFR** (frontend filter intent: filter cards, Match All=AND / Match Any=OR→UNION, X/Y axes, temporal relations) → **FAST** (semantic IR, modeled on HL7 CQL ELM, adds LeftJoin/HAVING/binning/patient-population split) → **AST** (visitor passes: alias mgmt, scope resolution, default-filter injection, concept-hierarchy expansion, date sentinels) → **SQL** (per-dialect: CTEs default, HANA anonymous blocks, nested subqueries, combined-count FULL OUTER JOIN). UUID-typed parameterization (injection-safe); censoring thresholds protect small cohorts. Reads CDW config every request.
- **CDW Configuration Service** — registry/editor of CDM configs mapping clinical concepts → physical tables via placeholders (`@PATIENT`, `@INTERACTION`, `@CODE`, `@MEASURE`...) + schema substitution (`$$SCHEMA$$`). Draft/Active/Inactive lifecycle. Structural + live-DB validation. Supports OMOP, EAV, custom star schemas; interface-view/direct-table/guarded (row-level security) mappings. Outage halts new queries.
- **PA Configuration Service** (`mri-pa-config`) — UI-level config for Patient Analytics (filter cards, attributes as category/measure, chart options, panel options). Every PA config references a CDW config. Three views (frontend/backend/admin). Not in query hot path.
- **Bookmark Service** — persists/shares full IFR query state as versioned JSON; no own DB (proxies Portal). Bidirectional cohort linkage; delete cascades to linked cohorts via Analytics.

## Data Management
- **User Management** (`alp-usermgmt`, Express) — authorization plane (Logto = authentication). Dual record: Logto identity ↔ local PostgreSQL roles/tenants/studies. Three-tier roles: System → Tenant → Study. Self-service access requests (approve by study manager). Enriches JWT with platform claims at sign-in so downstream services read claims, not the service.
- **Dataset Service** — only path to make a dataset queryable; threads schema provisioning (via Job Plugins/Prefect), Portal metadata registration, and access-grant init. Types: Source (direct OMOP) and FHIR (R4→OMOP via structure maps). Schema options: create/existing/custom/no-CDM. Visibility: Hidden/Normal/Public.
- **Portal Service** (`/system-portal`) — metadata system-of-record: datasets, studies, user-dataset maps, typed config (public vs secret with `[REDACTED]` round-trip protocol), feature flags, tags. Read by nearly every service; soft-delete + audit envelope (GxP/HIPAA). Backs Bookmark Service. Outage degrades the whole platform.

## OHDSI Integration
- **D2E WebAPI** (`/d2e-webapi`, Fastify :4949) — implements the OHDSI WebAPI surface so Atlas/Hades/Strategus talk to D2E under its auth. Cohort definitions (async OHDSI SQL gen via Job Plugins), concept sets (with deletion protection), vocabulary search/hierarchy. **TrexDAO** dual backend: TrexSQL (fast vocab) + SAP HANA (authoritative CDM).
- **Terminology Service** (`/terminology`, Express) — vocabulary lookup; **hybrid search: `score = α·cosine(embeddings) + (1−α)·trigram`**. FHIR R4 terminology ops (`$expand`, `$translate`). Dual backend (TrexSQL preferred, HANA fallback). Read-only on vocab.
- **Concept Mapping Service** — source vocab → OMOP standard concepts (e.g. ICD-10 → concept). Embedding-based suggestions (top-3 from Terminology, human decides). Atomic full-replacement per source vocab. zlib+base64 compressed payloads. Used by ETL/data engineers, not researchers.
- **OHDSI Tools** — White Rabbit (source DB profiling → Excel scan report, Java), Perseus (ER-model visualization), Strategus (HADES module orchestration → per-study R Shiny viewer proxied through Caddy). Each launched via Job Plugins, tracked via Prefect; they don't call each other.

## Infrastructure
- **Job Plugins Service** — gateway in front of Prefect; translates job submissions → Prefect deployment runs, adding auth, retries, per-tenant concurrency limits. Registry = `trex.plugins` table (logical op → deployment + JSON Schema, used for validation + frontend form generation), populated by `alp-dataflow-gen-init`. 16 controllers (Cohort, DQD, DataCharacterization, DataTransformation, WhiteRabbit, Perseus, Strategus, Cachedb...). Issues scoped least-privilege callback tokens.
- **AI Services** — Code Suggestion (LangChain ReAct agent, SSE-streamed, multi-model via `AI_MODEL`: Anthropic Claude / OpenAI / Azure / local), MCP Server (exposes cohort/phenotype/Strategus ops to external LLM clients via Model Context Protocol), Data Mapping (AI ETL: LLM drafts source→OMOP column mappings, unmappable → `concept_id = -1`).
- **File/Export** — Files Manager (PostgreSQL large objects, MD5 dedup, streaming) and Parquet Export (parameterized SQL templates only, never raw SQL; Trex `COPY` → temp file → stream → delete).
