Supabase Studio — sidecar not running

The @trex/studio plugin is registered, but no Studio sidecar is configured. Set TREX_STUDIO_URL on the trex container and the web shell will iframe it directly.

Why a sidecar (not static export)

Studio has ~92 internal Next.js API routes that don't survive output: 'export'. The pragmatic path is to run the official supabase/studio image as a separate container.

Enable
  1. Open docker-compose.yml and uncomment the studio service block.
  2. Set SUPABASE_ANON_KEY and SUPABASE_SERVICE_KEY in your .env — read them from trex.setting via the admin endpoint /trex/api/settings/auth-keys.
  3. Set TREX_STUDIO_URL=http://localhost:3001 on the trex container so the web shell knows where to iframe.
  4. Restart: docker compose up -d.
Trex endpoints Studio talks to 
SUPABASE_URL          http://trex:8001/trex
STUDIO_PG_META_URL    http://trex:8001/trex/pg/v1
auth                  /trex/auth/v1
rest                  /trex/rest/v1
storage               /trex/storage/v1
functions             /trex/functions/v1
graphql               /trex/graphql
realtime              not available in trex
vault                 not available in trex (no pgsodium)
Caveats

Studio has its own session and login screen — it doesn't share trex's Better Auth session. The Realtime tab and Vault tab will surface errors at runtime, since trex doesn't ship those services.
